# Hospital_management_system (python)
A hospital needs a computerized system to manage its day-to-day administrative and clinical relationships between staff and patients. The hospital currently employs two categories of healthcare workers, doctors and nurses who, despite performing very different clinical roles, share a common set of administrative attributes: a name, a unique employee ID, and a salary. Rather than duplicating this shared information across two unrelated structures, the system should model doctors and nurses as specialized types of a more general healthcare employee, allowing each to inherit the common attributes while extending them with role-specific details. A doctor, for instance, must additionally record a medical specialty, while a nurse must record the shift they are assigned to work. Both roles are expected to perform their duties differently, so the system must support behaviour that varies by employee type even though both are treated as healthcare employees at a structural level.
Since hospital records must be retained beyond the runtime of any single session, the system needs a persistence mechanism: all department, staff, patient, and appointment information must be saved to a human-readable file called hospital_records.txt so it can be reviewed later, and previously saved records should remain accessible even after the program restarts. Additionally, the hospital wants ongoing visibility into total staffing levels, requiring the system to track how many healthcare employees have been registered
